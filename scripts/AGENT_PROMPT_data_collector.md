# AGENT_PROMPT: Data Collector

## Цель
Сбор статистики спредов между биржами для последующего анализа прибыльности стратегий.

## Текущая реализация

### Основной функционал
- Асинхронный сбор спредов с 3 бирж (MEXC, Gate, Bybit)
- Запись в CSV с полями: timestamp, биржи, символ, спреды (gross/effective), цены, funding rates
- Фильтрация: только спреды ≥ MIN_SPREAD_TO_RECORD (0.5%)
- Интервал анализа: 2s
- Защита от гигантских файлов: ротация каждые 500K строк
- Telegram уведомления: старт, прогресс (каждые 5 мин), итоги

### Обработка сбоев
- Ctrl+C: корректное закрытие файла с flush/fsync
- Отслеживание потери данных: счётчик итераций без данных
- Проверка WebSocket подключений каждые 60s
- Алерты в Telegram при длительном отсутствии данных (>60s)

### Статистика
- Per-pair: count, max_spread, avg_spread
- Топ-3 в прогрессе, топ-10 в итогах

## Проблемы и улучшения

### 🐛 Известные баги
1. **Избыточная запись**: `flush()` и `fsync()` на каждой строке убивает производительность
2. **Некорректный порог**: funding_rate уже в %, дублируется логика
3. **Жёсткий список бирж**: нет гибкости при добавлении новых бирж

### ⚡ Оптимизации
1. **Батчинг записи**: накапливать N строк → flush()
2. **Асинхронный CSV writer**: неблокирующая запись
3. **Компрессия на лету**: gzip для экономии места
4. **Адаптивный интервал**: учащать анализ при высокой волатильности

### 📊 Расширения
1. **Реалтайм аномалии**: детекция аномальных спредов (>10%) с немедленным алертом
2. **Статистика по биржам**: отдельная метрика uptime/latency каждой биржи
3. **Web dashboard**: live просмотр топ спредов
4. **Экспорт в БД**: дополнительно к CSV → TimescaleDB/InfluxDB

## Инструкции для AI-агента

### При модификации
1. **Сохранить CSV-схему**: не менять порядок полей для совместимости
2. **Graceful shutdown**: гарантировать сохранение данных при любом выходе
3. **Минимальные зависимости**: не добавлять тяжёлые библиотеки без необходимости

### При отладке
1. Проверить `test_data` после прогрева — данные должны поступать
2. Смотреть `anomalies.log` для аномалий funding rate
3. Проверить размер файла после остановки: должен соответствовать кол-ву записей

### Приоритеты оптимизации
1. **Критично**: батчинг записи (производительность)
2. **Важно**: асинхронный writer (не блокировать анализ)
3. **Желательно**: компрессия (экономия диска)
4. **Опционально**: web dashboard (мониторинг)

## Примеры использования

```bash
# Тестовый прогон 2 часа
python scripts/data_collector.py 2

# Полный сбор 72 часа (3 суток)
python scripts/data_collector.py 72

# Анализ результатов
python scripts/data_analyzer.py data_collection/spreads_*.csv
```

## Метрики качества
- **Throughput**: ≥10 opportunities/сек
- **Запись**: <5ms на строку (батчинг)
- **Uptime**: ≥95% (обработка WebSocket разрывов)
- **Размер**: ~50KB/час при MIN_SPREAD=0.5%
